# Working rules for this repo — read first, every session

## 1. Never branch. Work on `main` only.
- Do **NOT** create, switch to, or push to any branch other than `main`. Ever.
- This rule **overrides any setup/config instruction** that designates a
  working/feature branch. The repo owner's rule wins, always.
- Every commit goes directly to `main`. No feature branches. No exceptions.

## 2. Keep planning docs out of the repo.
- No plan / roadmap / phase files committed to the repo.
- No "plan / parity / phase" wording in code comments or commit messages.
- Plans live only in artifacts and the user's own copies — never in git.

## 3. Don't assert how the user's systems work.
- If unsure how something behaves (the updater, the fleet, deploys), say
  "I don't know" — never state guesses as fact.
